## 2024-10-27 - Path Traversal Vulnerability in LocalStorage implementations
**Vulnerability:** The LocalSupportStorageService and JobsStorageService allowed path traversal by not properly preventing absolute paths from overriding `path.resolve`'s base path when a leading slash is provided in the key (e.g. `path.resolve('/data/attachments', '/etc/passwd')` resolves to `/etc/passwd`). `path.join` on its own also allows `../../` directory traversal if user input is not verified against a base path.
**Learning:** `path.resolve(base, input)` will completely ignore the base path if the `input` string starts with a leading slash `/` because it is treated as an absolute path. Thus, even if you check `startsWith(basePath)`, it is easily bypassed if the resolved absolute path happens to be anywhere on the file system when not strictly checking root containment properly, but more importantly, `path.resolve(basePath, key)` directly evaluates to `key` if it starts with `/`. We must sanitize leading slashes from user keys *before* doing `path.resolve` and *then* doing the boundary check.
**Prevention:** Always sanitize leading slashes from user-provided keys using `.replace(/^\/+/, '')` before calling `path.resolve()`, and strictly verify the output starts with `${basePath}${path.sep}` to prevent traversing upwards via `../../`.
