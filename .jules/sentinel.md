## 2026-09-16 - Prevent Object Injection in Platform Plans API
**Vulnerability:** The PlatformPlansController was accepting `any` for request bodies (`@Body() body: any`), allowing attackers to potentially bypass type checks and inject arbitrary NoSQL/Prisma objects into the database queries, leading to Object Injection vulnerabilities.
**Learning:** In NestJS, when `@Body()` is typed as `any` or an inline interface instead of a DTO class with validation decorators, `class-validator` is bypassed. This allows attackers to send nested objects (like Prisma operators `{ "contains": "admin" }`) instead of primitive types, compromising data integrity and security.
**Prevention:** Always use properly defined DTO classes with explicit validation decorators (e.g., `@IsString()`, `@IsNumber()`) and `PartialType` for update operations. Never use `any` or inline interfaces in `@Body()`. Ensure `class-validator` and `class-transformer` are properly configured globally in the application.
