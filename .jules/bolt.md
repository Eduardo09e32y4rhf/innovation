## 2024-05-15 - [Backend Performance: N+1 in Time Closing]
**Learning:** Found a major N+1 query issue in \`apps/api/src/modules/time-track/time-closing.service.ts\` during the payroll generation process. The \`generate\` method was looping through potentially hundreds of employees and running three database queries inside the loop (\`timeTrack\`, \`timeOccurrence\`, and \`userSchedule\`). This caused O(N) database queries per time closing run. I learned to use the \`$in\` operator combined with \`Promise.all\` and \`Map\` structures in Javascript to transform this into an O(1) query set (just 3 bulk queries total instead of 3*N queries).
**Action:** When finding \`findMany\` inside loops iterating over users/employees, replace it with bulk fetches that extract the \`employeeIds\` up front, pull all records with \`{ employeeId: { in: employeeIds } }\`, and group them in memory using \`Map\`.
