## 2024-07-30 - Accessible Interactive Elements in Inputs
**Learning:** When absolutely positioning interactive elements like toggle buttons inside input fields (e.g., password visibility toggles), they often lack focus styles and have `tabIndex={-1}` by default, making them completely inaccessible to keyboard users. When fixing this, you must explicitly define `focus-visible:ring-inset` alongside standard focus rings so the ring doesn't clip awkwardly outside the input's bounding box.
**Action:** Always verify `tabIndex` and focus styles (`focus-visible`) on floating buttons within inputs, ensuring they have appropriate ARIA labels and `aria-hidden` on internal icons. Use `focus-visible:ring-inset` for a polished visual result.

## 2024-08-20 - Ensure wrapper components spread props safely and cleanly
**Learning:** When creating wrapper components over basic HTML elements (like `button`), spreading all `...props` into the underlying native element ensures accessibility attributes like `aria-label` are supported. However, when the wrapper also injects default classes via string templates (e.g. `${className}`), it's crucial to handle `className` explicitly to prevent 'undefined' appearing in the class list if not provided, while retaining full HTML prop compatibility.
**Action:** When refactoring custom components (like `TableActionButton`) to support accessibility props, strictly extend `React.ButtonHTMLAttributes<HTMLButtonElement>`, extract `className`, handle its default stringification carefully (e.g., using `${className || ''}.trim()`), and pass down `...props` to natively support ARIA and title attributes without cluttering the component's custom interface.
