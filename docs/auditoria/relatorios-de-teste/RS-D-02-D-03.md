# RS-D-02 e RS-D-03 — documentos na contratação

**RS-D-03.** Antes: `POST /jobs/applications/:id/hire` criava o funcionário sem olhar os documentos. Agora `JobsService.hire` consulta `RecruitmentDocumentsService.hiringKitStatus`; se faltar documento obrigatório aprovado, responde 400 listando os itens. Exceção: `skipDocumentCheck` + `skipDocumentReason` (≥10 caracteres), gravada no AuditLog como `HIRE_DOCUMENTS_OVERRIDE` com os itens faltantes. Sem documentos exigidos pela vaga, nada muda. A tela de contratação ganhou a caixa de exceção com justificativa.

**RS-D-02.** Na transação da contratação, cada documento aprovado e vigente vira um `Attachment` EMPLOYEE do novo colaborador, apontando para `/jobs/documents/:id/download` (arquivo único, cifrado, só RH, com auditoria de leitura; sem cópia em claro).

**Testes:** `hire-documents-gate.spec.ts` (3), `hire-dossier.spec.ts` (1); jobs + contract: 83 arquivos / 646 testes; tsc API e web limpos.
**Não verificado:** fluxo no navegador e que a tela de documentos do colaborador exibe esses anexos pelo link do download.
