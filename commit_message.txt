🎨 Palette: [UX improvement] Improve login form accessibility

💡 What:
- Associated all `label` tags with their respective `input` elements using `htmlFor` and `id` attributes.
- Added a dynamic `aria-label` ('Ocultar senha' and 'Mostrar senha') to the icon-only "show/hide password" button.
- Added `aria-hidden="true"` to the inner decorative SVGs within the toggle button.
- Added a clear focus state (`focus-visible:ring-2`) to the toggle button.
- Resolved Node.js 20 deprecation warnings in CI workflows.

🎯 Why:
To ensure the login form is fully accessible to screen readers by providing proper context for all inputs, and to improve keyboard navigation by making the focus state of the password visibility toggle clearly visible.

📸 Before/After:
Before: The toggle button lacked an ARIA label, the SVGs were read by screen readers, and the button had no visible outline when focused with the keyboard. Labels were not linked to inputs.
After: The toggle button clearly announces its dynamic action, the SVGs are hidden from screen readers, and the button has a visible purple outline when focused via keyboard. All labels correctly focus their respective inputs when clicked.

♿ Accessibility:
- Fixed missing explicit associations between `<label>` and `<input>` (WCAG 1.3.1).
- Fixed missing name for icon-only button via `aria-label` (WCAG 4.1.2).
- Prevented redundant and potentially confusing screen reader announcements by hiding decorative SVGs (WCAG 1.1.1).
- Improved focus visibility for keyboard users (WCAG 2.4.7).
